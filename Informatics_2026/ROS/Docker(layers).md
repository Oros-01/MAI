# Docker: слои и кэш (конспект)

## Слои
- Каждый `RUN` / `COPY` / `ADD` / `ENV` / `WORKDIR` — отдельный слой.
- Слой берётся из кэша, если:
  - его инструкция не изменилась **и**
  - родительский слой тот же (тот же, что в прошлой сборке).
- Изменил/вставил/переставил инструкцию → **все последующие слои пересобираются** (не «подкачиваются»), т.к. у них меняется родитель.
- Цепная реакция: один слой пересобрался → все ниже тоже.

## Порядок в Dockerfile
- Редко меняющееся — в начало (`FROM`, `ENV`, базовые `apt install`).
- Часто меняющееся — в конец (`COPY` кода, `colcon build`, `CMD`).
- Встраивание в середину — дорого (ломает кэш для всего ниже).
- Добавление в конец — дёшево (ломает кэш только для нового слоя).

## Объединение пакетов в один `RUN`
- Плюс: меньше слоёв, меньше образ, быстрее финальная сборка.
- Минус: меняешь один пакет в `RUN` — пересобираются **все** пакеты в этом `RUN`.
- «Встроить файл в готовый слой» нельзя — слои неизменяемы. Можно только заранее объединить пакеты в одну инструкцию.

## Вывод
- Стабильное — вверх, изменчивое — вниз.
- Связанные `apt install` — в один `RUN`, помня про цену изменения.
- Новый пакет отдельным `RUN` в конце — дешевле по кэшу, но +1 слой. Для домашки не критично.
- Не трогать ранние слои (репозиторий ROS, базовые пакеты) без необходимости.
