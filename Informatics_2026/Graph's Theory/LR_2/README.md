# LR_2 — задание №2 по теории графов (на «4»)

**Вариант `bbbb`, № 13 по списку — нечётный.**

| Что | Значение для №13 (нечётный) |
|---|---|
| Часть 1: вход | **матрица пропускных способностей** (поддерживаются и списки смежности) |
| Часть 1: алгоритм | Форд-Фалкерсон, версия с поиском пути в ширину (Эдмондс-Карп) |
| Часть 2: алгоритмы | **Дейкстра и A\* с эвристикой Чебышева** |
| Часть 3 | двудольность + максимальное паросочетание (от чётности не зависит) |

## 1. Структура проекта

Разделение файлов такое же, как в ЛР1 — ядро / алгоритмы / исполнительский файл:

| LR_1 | LR_2 | Что внутри |
|---|---|---|
| `graph.h` | `core.h` | объявления: три структуры и функции алгоритмов |
| `graph.cpp` | `core.cpp` | **ядро**: чтение входных файлов |
| `graph_algo.cpp` | `algo.cpp` | **алгоритмы**: Форд-Фалкерсон, Дейкстра, A\*, Куна |
| `main.cpp` | `main.cpp` | **исполнительский**: аргументы, вызов части, запись результата |

```
LR_2/
├── core.h            объявления
├── core.cpp          ядро: чтение трёх форматов
├── algo.cpp          три алгоритма
├── main.cpp          запуск и вывод
├── data/             тестовые входные файлы
├── build.bat         сборка
└── README.md         этот файл
```

В ЛР1 был один класс `Graph`, потому что граф один. Здесь три части задания работают
с разными данными (сеть, карта, двудольный граф), поэтому структур тоже три —
по одной на каждую часть, каждая объявлена один раз.

## 2. Сборка

Нужен `g++` с поддержкой C++17 (MinGW):

```bat
build.bat
```

или вручную:

```bat
g++ -std=c++17 -O2 -Wall -Wextra -o lr2.exe core.cpp algo.cpp main.cpp
```

## 3. Запуск

Первый аргумент — **номер части задания**. Ключ `-o` задаёт файл результата;
если его нет, результат пишется в `ans.txt` (как требует задание).

```bat
lr2.exe 1 data\net.txt
lr2.exe 1 data\net.txt -o out_flow.txt

lr2.exe 2 data\map_big.txt -a 1 1 -b 20 20
lr2.exe 2 data\map_big.txt -a 1 1 -b 20 20 -o out_path.txt

lr2.exe 3 data\bip.txt
lr2.exe 3 data\bip.txt -o out_match.txt
```

Координаты в ключах `-a` и `-b` нумеруются с 1: сначала **строка**, потом **столбец**.

Без аргументов открывается меню — удобно для показа на защите.

## 4. Форматы входных файлов

Во всех файлах строки, начинающиеся с `#`, считаются комментариями.

### Часть 1 — транспортная сеть (`data/net.txt`)

```
1 6
0 16 13  0  0  0
0  0  0 12  0  0
...
```

Первая строка — `<источник> <сток>`. Дальше **матрица N × N**:
`cap[u][v]` — пропускная способность дуги `u -> v`, ноль означает, что дуги нет.

Дополнительно поддерживается второй формат — **списки смежности**
(`data/net_list.txt`):

```
1 6
1 2 16 3 13
2 4 12
```

Строка: `<вершина> <сосед> <пропускная способность> <сосед> <вес> ...`

Формат определяется автоматически: если каждая строка тела файла имеет длину,
равную количеству строк, — это матрица, иначе — списки смежности.

### Часть 2 — карта высот (`data/map.txt`, `data/map_big.txt`)

Каждая строка файла — строка карты, числа разделены пробелами.
Высота `0` означает, что прохода нет (стена).

### Часть 3 — двудольный граф (`data/bip.txt`, `data/bip_not.txt`)

Формат 1 — матрица смежности: первая строка `N`, дальше матрица `N × N`,
ненулевое значение означает ребро.

Формат 2 — список рёбер: по паре `<u> <v>` в строке.

Формат определяется автоматически.

## 5. Ожидаемые результаты (проверено)

### Часть 1

```
lr2.exe 1 data\net.txt -o out_flow.txt
Максимальный поток = 23
```

Содержимое `out_flow.txt`:

```
Источник: 1
Сток: 6
Суммарная величина потока: 23

Рёбра сети (дуга, поток, пропускная способность):
  1 -> 2   поток = 12   пропускная способность = 16
  1 -> 3   поток = 11   пропускная способность = 13
  2 -> 4   поток = 12   пропускная способность = 12
  3 -> 2   поток = 0   пропускная способность = 4
  3 -> 5   поток = 11   пропускная способность = 14
  4 -> 3   поток = 0   пропускная способность = 9
  4 -> 6   поток = 19   пропускная способность = 20
  5 -> 4   поток = 7   пропускная способность = 7
  5 -> 6   поток = 4   пропускная способность = 4
```

Тот же ответ `23` даёт и `data/net_list.txt` — это проверка того,
что оба формата читаются одинаково.

Ответ сходится с проверкой: в вершину 6 входит `19 + 4 = 23`, и сумма
потоков из источника `12 + 11 = 23`.

### Часть 2

На большой карте 20 × 20 разница между алгоритмами видна:

```
lr2.exe 2 data\map_big.txt -a 1 1 -b 20 20 -o out_path_big.txt
  Дейкстра: длина 30, просмотрено 94%
  A* (эвристика Чебышева): длина 30, просмотрено 62.25%
```

**Длина пути у обоих одинаковая — это главная проверка правильности.**
A\* находит тот же кратчайший путь, но просматривает меньше вершин (62% против 94%),
потому что эвристика подсказывает ему направление к цели.

На маленькой карте 8 × 8 (`data/map.txt`) разница почти исчезает:
оба просматривают 96.875% вершин, длина 19. Это нормально: на 64 клетках
выигрыш эвристики просто не на что потратить.

### Часть 3

```
lr2.exe 3 data\bip.txt -o out_match.txt
Граф является двудольным: да
Число паросочетаний: 3
Размер максимального паросочетания: 3
Рёбра, входящие в паросочетание:
  1 - 4
  3 - 5
  2 - 6
```

```
lr2.exe 3 data\bip_not.txt -o out_match_not.txt
Граф является двудольным: нет
```

`data/bip_not.txt` — это треугольник `1-2-3-1` (нечётный цикл), он не двудольный.

> В задании два пункта названы «число паросочетаний» и «размер максимального
> паросочетания». Для максимального паросочетания это одно и то же число
> (число рёбер = размер), поэтому в отчёте обе строки совпадают.

## 6. Шпаргалка к защите

### Часть 1: Форд-Фалкерсон

**Идея в одном предложении:** пока в остаточной сети есть путь из источника в сток —
пускаем по нему поток и прибавляем его к ответу.

Что важно сказать:

* **Остаточная сеть.** По дуге `u -> v` можно пропустить ещё `cap[u][v] - flow[u][v]`.
  Когда мы пускаем поток по дуге, у встречной дуги значение `flow` уменьшается —
  это и есть «возможность отменить поток назад». Поэтому в коде есть строка
  `flow[v][u] -= push`.
* **Версия алгоритма.** В задании сказано «соответствующую версию». Реализована
  версия, где путь ищется **в ширину (BFS)** — она же алгоритм Эдмондса-Карпа.
  Почему так лучше: BFS всегда даёт путь с минимальным числом рёбер, поэтому
  алгоритм гарантированно завершается за `O(V · E²)`. DFS-версия тоже работает
  при целых пропускных способностях, но обосновать её сложнее.
* **Когда останавливаемся.** Когда BFS не смог дойти от источника до стока —
  значит, увеличивающих путей больше нет, поток максимален.

### Часть 2: Дейкстра и A\*

**Дейкстра — это A\* с нулевой эвристикой.** Поэтому в `algo.cpp` одна функция
`find_path(...)` с флагом `use_astar`, а не две одинаковые.

* **Стоимость шага** — `max(1, |h1 − h2|)`, то есть перепад высот, но не меньше 1.
* **Соседей 8** — включая диагонали.
* **Эвристика Чебышева:** `h = max(|dr|, |dc|)` — минимальное число шагов
  по диагонали и по прямой до цели.
* **Почему A\* не врёт.** Любой шаг стоит хотя бы 1, а за один шаг ни одна
  координата не меняется больше чем на 1. Значит до цели нужно минимум
  `max(|dr|, |dc|)` шагов, то есть эвристика никогда не завышает длину —
  она **допустимая**. Поэтому длина пути у A\* и Дейкстры совпадает.
* **Что сравниваем.** `%` просмотренных вершин и время — это и есть смысл задания.

### Часть 3: двудольность и паросочетание

Это **два разных шага**:

1. **Раскраска в 2 цвета** (обход в ширину). Соседям даём противоположный цвет.
   Если нашли двух соседей одного цвета — граф не двудольный (есть нечётный цикл).
   Если двудольный — заодно получили деление на левую и правую доли.
2. **Алгоритм Куна.** Перебираем левые вершины. Для каждой ищем **увеличивающую
   цепь**: свободное ребро вправо, потом занятое ребро влево, потом опять свободное
   вправо… и так до свободной правой вершины. Нашли цепь — паросочетание выросло
   на 1. Сложность `O(V · E)`.

Раскраска нужна Куну как подготовка: без деления на доли он не знает,
откуда искать цепи.
